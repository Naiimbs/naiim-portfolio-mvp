# أمثلة تحليل حقيقية — موقع Naïm Bsili

هذه الأمثلة توضّح شكل النتيجة المبنية على ملفات حقيقية عند استعمال الـ Prompt على Repository الموقع. نفرّق فيها بين النتائج المؤكدة والافتراضات. هذه نتائج تحليل وليست أوامر لتعديل الإنتاج.

## المثال 1 — نشر Prompt جديد عبر CMS

**الهدف:** نشر Prompt لتحليل البرمجيات بعدة لغات، مع صفحة تفاصيل، زر نسخ، ملفات للتحميل، وRoute عامة.

**المؤكد من المشروع:** الموقع مبني بـ React وVite. صفحة تفاصيل الـ Resource موجودة في `src/pages/ResourceDetailPage.jsx`، وبطاقات الكتالوج في `src/pages/ResourcesPage.jsx`، وتطبيع بيانات الموارد في `src/services/resources.js`، بينما الكتالوج الحي يعتمد على Supabase `content_registry`. النشر يتم عبر `.github/workflows/manual-vps-deploy.yml`.

**مسار الكود المعني:** الـ Route هي `/resources/:slug`. المعايير الخاصة بنوع Prompt معرفة في `src/config/resourceTypeDetails.js`. صفحة التفاصيل تقرأ `prompt_format` و`model_compatibility` و`variables` و`example_input` و`example_output` و`safety_notes` من Metadata الـ CMS.

**المخاطر المؤكدة:** يمكن أن يكون السجل صحيحاً في Supabase بينما الملفات المرتبطة غير موجودة في النسخة المنشورة. الترتيب الآمن هو نشر الملفات أولاً ثم نشر سجل CMS. كما يمكن أن تتعارض Route التي تحمل نفس اسم مجلد `public/resources/<slug>` مع أولوية Nginx.

**الخطة المقترحة:** أضف الملفات المترجمة وتحقق منها، انشر الـ assets، أنشئ سجل `content_registry` بحالة `published` ونوع `prompt` ومعاييره الخاصة وترجماته وأمثلته وروابطه، ثم تحقق من الصفحة وزر النسخ وتغيير اللغة وملف ZIP.

## المثال 2 — تشخيص خطأ 403 في صفحة Resource

**الهدف:** فهم لماذا يمكن أن ترجع `/resources/project-analysis-architect-prompt` خطأ 403 رغم أن ملفاتها ترجع 200.

**النتيجة المؤكدة:** يحتوي `nginx.conf` على قاعدة خاصة بـ Routes الموارد ذات الجزء الواحد. القاعدة القديمة كانت تختبر `$uri/`، وفي نفس الوقت يوجد مجلد بنفس الـ slug داخل `public/resources`. لذلك حاول Nginx معالجة المجلد بدل تمرير الطلب إلى تطبيق React، فظهر 403 Forbidden.

**خطة الإصلاح الدنيا:** نحافظ على خدمة الملفات العميقة، لكن نجعل Route ذات الجزء الواحد تنتقل إلى `/index.html` دون اختبار المجلد نفسه. بعد ذلك نختبر الكتالوج وصفحة التفاصيل وملفات Markdown وZIP بشكل منفصل.

## المثال 3 — تدقيق تدفق تحميل بمساعدة AI

**الهدف:** السماح للـ contacts المعروفين بالتحميل مباشرة، وطلب الاسم واللقب والدور من الـ contacts الجدد، مع بقاء الواجهة مترجمة.

**المسارات المؤكدة:** الـ Modal موجودة في `src/components/resources/ResourceLeadFormModal.jsx`، واتصالات التسويق في `src/services/marketing.js`، والـ Edge Function `resource-ingest` في Supabase تعالج الطلب.

**حدود الأمان المؤكدة:** لا يجب أن يقرر المتصفح وحده هل البريد موجود أم لا. يجب على الوظيفة في الخادم التحقق من الطلب وتطبيق rate limits وفحص النطاقات المؤقتة، ثم تقرير هل يجب طلب بيانات الملف الشخصي.

**الاختبارات المقترحة:** Contact موجود، Contact جديد صحيح، نطاق مؤقت، بريد غير صالح، طلبات متكررة، Resource غير منشور، نصوص EN/FR/AR، وفشل التحميل بعد تسجيل الـ lead بنجاح.
